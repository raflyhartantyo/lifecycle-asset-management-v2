# Monthly Book Value adjustment — design outline

Status: owner-approved requirement D046; formula and implementation deferred. No scheduled flow definition is delivered or running. This is a future addition to the target flow set, not a statement that one of the 15 baseline reference flows implements it.

## Confirmed business requirements

- Currency is IDR throughout LAM.
- Purchase date and purchase cost are mandatory business inputs, validated by the application (D044).
- Book Value is calculated using a formula to be supplied later.
- A scheduled flow adjusts Book Value at the start of every month.
- Asset Tags are generated by LAM; their format/allocation scheme remains deferred (D043).

## Proposed engineering behavior

1. Determine a single accounting/calculation period using the configured business time zone and the approved formula version. The time zone and exact run time remain TBD.
2. Select eligible assets using indexed, complete queries. Plan for approximately 5,000 assets overall and up to 2,500 per entity; a default connector page is not the processing contract. Final eligibility rules remain TBD.
3. Validate formula inputs at the mutation boundary. Missing data is reported per asset rather than silently replaced with zero or a guessed input. SharePoint optional storage fields do not remove application business validation.
4. Calculate using the approved formula, effective period and agreed precision/rounding. Do not select a depreciation method, useful life or residual value until explicitly supplied/confirmed.
5. Record a monthly run ID and a per-asset calculation/application outcome, with asset ID, period, formula version, inputs/reference version, previous/new Book Value, calculation timestamp, execution identity and failure detail. Final list/column definitions follow later.
6. Use a durable per-asset/period operation identity, together with explicit versioning for authorized recalculation, so an ordinary retry cannot apply the same adjustment twice. A prior write whose outcome is uncertain must be reconciled rather than blindly repeated. Do not derive the business period solely from the retry's current date.
7. Detect concurrent asset edits, disposal, transfers and reconciliation corrections; revalidate before writing and route conflicts for recovery. Define serialization/version rules with the other mutation flows. A calculation and its asset update/audit are not assumed to be a single atomic transaction in SharePoint.
8. Finish with expected/selected/succeeded/skipped/failed/conflicted counts. Incomplete processing remains visibly partial; support safe resumption of failed assets without recalculating already applied rows. Never report the run complete while silently truncating the asset set.

These are engineering proposals to support the requirement, not an approved accounting formula or tested implementation. Scheduling mechanics, owner/connection configuration, licensing and available actions need verification with the final implementation.

## Relation to reconciliation

Book Value generation and ledger comparison are different operations. The monthly calculation will generate the register's value using the approved formula; reconciliation can compare it with accounting data and preserve differences/provenance. Accounting/Governance sign-off and the Asset Manager's explicit correction step remain separate under D036–D038 and D070: explicit authorized application comes before final sign-off on actual results. No upload automatically overwrites Book Value. Authority and rules for a reconciliation correction that conflicts with a formula result must be settled before deployment.

## Deferred decisions

Formula and input definitions; effective version dates; eligible/ineligible asset states; purchase/disposal timing; initial Book Value at registration; first/last-period treatment; precision/rounding and value floors; time zone/exact first-of-month run time; manual overrides and their persistence; missed-period catch-up; authorized recalculation/backfill; historic value/report requirements; reconciliation conflict handling; operational support/notification recipients.
